# 简化版 PCB 固件修改说明（omb-nano fork）

> 本文档记录针对"简化版 PCB"对上游 gauteh/omb-nano 固件所做的修改：改了哪些文件、为何改、编译方式与产物。
> 简化版 PCB 差异、DNP 元件清单依据：`buoy/docs/2.PCB备料与组装指南.md`、`buoy/docs/4.OMB_Nano_烧录固件.md`、`buoy/docs/4.1 代码修改.md`。
> 分阶段提交，每阶段编译验证后再 commit。

---

## 硬件背景（简化版 PCB）

- **主控**：SparkFun Artemis 模块（Apollo3 Blue，Cortex-M4F），编译/烧录只作用于这颗 MCU。
- **传感器**：IMU ISM330DHCX（I2C IOM0）、GNSS MAX-M10M（I2C IOM3，外接有源天线 AHGG.202 经 U11）。
- **新增**：microSD 卡座 CARD1（SPI）。
- **供电**：电池 → U5 S7V8F3（自焊）→ 3.3V；USB-C经U5可为主板供电；U27 HT7333-1仅给CH340供电。2026-11-14原型机U5未装，稳定3.3V飞线注入VOUT/VCC、GND，详见 `../../omb-nano-extend/docs/prototype-status.md`。
- **未贴（DNP）**：铱星 RockBLOCK 9603、板载天线链 E1/U21/L3/C17-19/R22/U20、超级电容 C30/C31、SW1 干簧开关；其中仅**铱星**对应活跃固件代码需改（其余为纯硬件或上游已注释）。

## Phase 1 — 去铱星（适配简化版 PCB，铱星模块未贴）  *(已完成，commit #2)*

- `src/params.h`：铱星参数区新增开关与说明，默认 `// #define USE_IRIDIUM`（注释/不定义）。将来真装模块时取消注释即可恢复铱星。
- `src/tracker.ino`：用 **`#ifdef USE_IRIDIUM … #endif`** 条件编译包裹**全部** `iridium_manager.*` 调用（发送/状态查询）、`any_successful_transmit` 声明、整个发送突发块；并把日志措辞改干净。保留 `#include "iridium_manager.h"` 与 `iridium_manager.cpp` 参与编译（`<IridiumSBD.h>` 库仍链接）。
  - 注意：正确方向是 `#ifdef`（宏未定义→剔除），非计划初稿误写的 `#ifndef`。
- 不改 `board_control.cpp`：其 `iridiumSleep`(p35) 写 LOW 在无模块时为无害空操作。
- 验证：编译通过，`src/build/tracker.ino.bin` 124648 字节（较 Phase 0 的 136376 减小约 11.7KB，未引用的铱星收发代码被 linker 剔除）。
- GNSS/IMU/波浪谱/睡眠/看门狗逻辑未改动，功能保留。

## Phase 2 — SD 卡数据记录（新增元件）  *(已完成，commit #3)*

- `src/Dockerfile`：`arduino-cli lib install "SdFat@2.2.3"` + sed 补丁把 `SPI_DRIVER_SELECT` 改为 2（启用软件 SPI；全局补丁以保证 SdFat 各编译单元一致）。
- `src/board_control.h`：SD 引脚 `SD_CS=27, SD_MOSI=26, SD_SCK=28, SD_MISO=25, SD_CD=22`（来自 PCB设计决策记录.md §六）。注明为软件 SPI（这些引脚不是硬件 IOM pad）。
- 新增 `src/sd_manager.h/.cpp`：`SoftSpiDriver<MISO=25,MOSI=26,SCK=28>` 软件 SPI + `SdFat32`；`GNSS.CSV`（posix,lat_1e7,lon_1e7）/ `WAVES.CSV`（posix,谱号,Hs,Tz,Tc,max,55 频段）追加写；每次 open→append→flush→close；**无卡时 setup() 优雅失败、所有写入安全跳过，不阻塞主流程**。
- `src/tracker.ino`：`setup()` 调 `board_sd_manager.setup()` 挂载；在初始/循环定位的 **GPS 断电后**、波谱 **IMU 停后** 调 `log_latest_*`（满足电流错峰时序）。
- 选 SdFat 软件 SPI 的原因：SD 引脚（25/26/27/28）是任意 GPIO，不对齐 Apollo3 任何硬件 SPI IOM 的 pad，故必须用 bit-banged 软件 SPI。
- 验证：重建镜像 + 编译通过，`src/build/tracker.ino.bin` 132104 字节（较 Phase 1 的 124648 增约 7.5KB = SdFat + 软件 SPI 代码）。
- 注意：编译通过不等于真机可用；软件 SPI 引脚时序与 SD 卡兼容性需真板验证（本轮按用户要求不做真机验证）。

### 烧录与 SD 卡

- `src/build/tracker.ino.bin` **同时适用于插卡与不插卡**两种情况：上电时 `setup()` 探测 SD，无卡则记录功能自动禁用，GNSS/IMU/波浪谱照常运行。无需为"不插卡"单独编译固件。

## Phase 3 — 波浪谱算法可靠性审计落地：扩带 2s（问题8）+ 逐段去尖峰（问题3）  *(已完成)*

> 背景：`docs/2.问题与结论.md` 是一份独立的波浪谱算法审计（对照 SWIFT/NIWA WII 参照浮标）+ 仿真报告，发现 8 类问题。其中问题1（Tz/Tc 公式写反）、问题6（缺 Tp 输出）已在更早阶段直接改代码修复（未单独在此记录 Phase，详见该文档）。本 Phase 记录仿真定量确认"值得改"之后，问题3、8 的具体固件改动。**先改这两个的原因**：它们改变浮标实际采集/回传的频段和数据格式（55格/3.25s → 94格/2s），下游岸上分析工具（`analysis/wave_spectrum_validation/code/wave_analyzer_enhance.py`，处理问题2/4）依赖这个格式，必须先定死。

- **`src/params.h`**：
  - `welch_bin_max` 由 **64 改为 103**（问题8，保留频段上限从 3.25s 扩到 2.0s，bin102≈0.498Hz）。核实只此一处常数需要改——`nbr_wave_packet_freqs = welch_bin_max - welch_bin_min` 自动 55→94，`Wave_Packet::array_pwelch[]`、`working_welch_spectrum[]` 及 `wave_analyzer.cpp`/`sd_manager.cpp` 所有循环边界均从它派生，FFT 长度 2048 足够覆盖 bin102（无越界风险）。
  - 新增 `use_despike`（bool，默认 `true`）、`despike_k_sigma`（`10.0f`）两个常数（问题3，轻量去尖峰开关与门槛）。
- **`src/wave_analyzer.cpp`**：`perform_welch_analysis_imu_data()` 里，段填充（减重力）之后、加窗之前，插入逐段去尖峰：算出该段自己的均值/标准差，把超出 `mean±despike_k_sigma*std` 的样本钳到边界值，O(N)、不额外分配缓冲区。仅在 `use_despike` 为真时执行。
- **格式后果**（问题8，非问题3——去尖峰不改变数据格式，只改变数值）：
  - 每包谱从 55 格变 **94 格**，`Wave_Packet` 增约 78 字节（约 218 字节，仍在 `iridium_tx_buffer_size=340` 内）。
  - `WAVES.CSV` 每行多 39 个谱列（`sd_manager.cpp` 自动适配，无需改动）。
  - `wave_packet_buffer` deque(128) 静态占用 RAM 增约 10KB。
- **验证**：Docker 编译通过，无警告。`Global variables` 从 104436 增至 **114476 字节**（+10040，与手算 128 包 × 78 字节 ≈ 9984 吻合，确认改动范围符合预期）；flash 使用 132352 字节（13%，Maximum 960000），较改动前 132224 增约 128 字节（去尖峰代码本身的开销，量级远小于问题8的格式扩展）。
- **下游影响**：任何按旧 55 格解析 `array_pwelch`/`WAVES.CSV` 的代码必须改为动态读取列数——岸上工具 `wave_analyzer_enhance.py::load_waves_csv` 已按此设计（谱列数从文件本身读取，不写死）。
- **未改动**：问题2（低频漂移）、问题4（QC盲区）判定为不改固件、留给岸上处理，详见 `2.问题与结论.md` §7 与 `analysis/wave_spectrum_validation/code/wave_analyzer_enhance.py`；问题5（窗修正系数）维持现状不改。

## 编译与产物

构建链 = 仓库 `Dockerfile` + `Makefile bin:` 目标。macOS（Docker Desktop 已装）：

```bash
export PATH="/Applications/Docker.app/Contents/Resources/bin:$PATH"
cd ~/Downloads/omb-nano
docker build -t omb-nano .
docker run --rm -v "$(pwd)/src:/tracker" omb-nano \
  bash -lc "arduino-cli compile -e --output-dir build --build-cache-path /tmp/build -v -b SparkFun:apollo3:artemis ."
```

- 产物：`src/build/tracker.ino.bin`（约 134KB 量级，对照 `firmware/omb_nano_v0.2.0.bin`）。
- 烧录：`arduino-cli upload -p <PORT> -b SparkFun:apollo3:artemis --input-file src/build/tracker.ino.bin`（串口 1,000,000 bps）。
