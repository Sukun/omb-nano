# 1. 波浪谱算法说明（omb-nano wave_analyzer）

> 本文档说明 omb-nano 浮标波浪谱算法**怎么工作**：从 IMU 加速度到 Hs/Tz/Tc/Tp 的完整流程与精确公式（参考层）。关于这套算法**有什么问题、多严重、怎么办**，见 [`2.问题与结论.md`](2.问题与结论.md)——那份是需要持续跟踪的状态文档，权威性高于本文档。

## 一、基础概念（大白话，先建立直觉）

尽量用大白话解释，不追求数学严谨，只求"知道这几个词在说什么"。

**海浪不是一个数字，是一堆波叠在一起。** 真实海面是无数不同频率、不同高度、方向随机的波叠加的结果。海洋工程不追踪每个波，而是统计地描述："这段时间海面整体有多高？平均起伏一次要多久？"

**几个常见海况参数：**
- **有效波高 Hs**："这段时间里最大的那 1/3 波浪的平均高度"，描述海况"多大"的单一数字；数学上 = 海面高度信号的标准差 × 4。
- **平均跨零周期 Tz**：海面从下往上穿过平均水位线，相邻两次穿越的平均间隔，即"波浪平均多久起伏一次"。
- **平均波峰周期 Tc**：相邻两个波峰的平均间隔，比 Tz 更关注"峰"、对高频噪声更敏感。
- **谱峰周期 Tp**：海浪能量最集中那个频率对应的周期，即"这片海最主要的波多久一个周期"。

这几个量都从同一条"海浪谱"用固定公式算出，彼此有严格数学关系——所以"问题1（公式写反）"会连累所有下游数字。

**什么是"海浪谱"：** 把海面高度曲线做傅里叶分解（拆成无数不同频率正弦波的叠加），每个频率分到的能量画成"频率 vs 能量"图，就是海浪谱。谱峰频率=海浪主导频率（对应 Tp），整条谱下方面积=总能量（决定 Hs）。

**IMU 测的是加速度不是波高——为什么除以 ω⁴：** IMU 直接测垂向**加速度**。物理上加速度谱与高度谱之间差一个固定系数 `ω⁴`（ω=2πf）——频率越高、同样高度的起伏产生的加速度越大，所以要把加速度谱除以 ω⁴ 才能倒推高度谱。副作用：**频率越低 ω⁴ 越接近 0，除法放大倍数越夸张**——这是"问题2"的核心机制。

**Welch 法：** 直接对几千个采样点做一次 FFT，谱会很"毛躁"。Welch 法把整段数据切成若干有重叠的小段、各自 FFT、再平均，磨平随机噪声。本固件把约 20 分钟数据切 21 段（每段 204.8s，重叠 75%），切段前每小段乘 Hann 窗抑制频谱泄漏（代价是需要能量修正系数补回损失，即"问题5"）。

**谱矩：** Hs/Tz/Tc 由对谱曲线加权积分（谱矩）得到——"谱下面积"（→Hs）、"面积按频率平方加权"（→Tz）、"按四次方加权"（→Tc）。所以**保留频率范围不够宽（问题8）或谱本身被漂移/尖峰污染（问题2/3），这些数字就跟着错**——这是几个问题共同的数学根源。

## 二、采集 → 处理 → 上传全流程（含传回的数据）

浮标芯片一步步做了什么、最后**传回岸上的数据具体是什么**：

```
┌─ 浮标芯片上（Apollo3 MCU + ISM330DHCX 六轴IMU）───────────────────────────┐
│  ① IMU 原始采样   加速度+角速度 @ 833 Hz（三轴，机体坐标系）              │
│         ▼  分块均值滤波（n-sigma 剔野值）                                 │
│  ② 100 Hz 加速度+角速度                                                   │
│         ▼  Kalman/AHRS 姿态融合（磁力计关闭）                             │
│  ③ 姿态：roll / pitch / yaw + 四元数                                      │
│         ▼  四元数旋转：机体系加速度 → 地理系(NED)                         │
│  ④ NED 三轴加速度：北 accel_N、东 accel_E、垂向 accel_D                   │
│         ▼  再分块均值 → 降采样到 10 Hz                                    │
│  ⑤ 10 Hz 加速度 —— ★只保留垂向 accel_D，北/东两路当场丢弃★               │
│         │            （DataEntry 结构体里只有 accel_down 一个字段）       │
│         ▼  攒够约 20.48 分钟（12288+99 点）                               │
│  ⑥ 一整段 10 Hz 垂向加速度时间序列                                        │
│         ▼  Welch 谱估计（减重力→分21段→去尖峰(mean±10σ钳位)→加Hann窗→FFT→平均）│
│  ⑦ 加速度功率谱 working_welch_spectrum（94个频格, 0.044–0.498 Hz）        │
│         ├─▶ 除以 ω⁴ → 位移谱 → 谱矩 m0/m2/m4 → Hs、Tz、Tc                 │
│         └─▶ 谱最大值那格 → Tp                                             │
│         ▼  归一化到 max_value，每格量化成 uint16(0–65000)                 │
│  ⑧ 打包 Wave_Packet { posix_timestamp, spectrum_number,                  │
│       Hs, Tz, Tc, Tp,  max_value,  array_pwelch[94] }                     │
└─────────┼────────────────────────────────────────────────────────────────┘
          ▼
   ⑨ 数据出口：写入 SD 卡 WAVES.CSV（本版实际数据汇）＋ USB 串口（台架）
      （原设计经 Iridium 卫星发送，简化版 PCB 未贴装铱星模块，代码路径保留但空转）
```

**传回岸上的每次测量 = 一个 `Wave_Packet`：**

| 字段 | 物理含义 | 类型 |
|---|---|---|
| `posix_timestamp` | 测量时刻（UTC 时间戳） | 整数 |
| `spectrum_number` | 第几次谱测量（计数器） | 整数 |
| `Hs` | 有效波高 | 浮点(m) |
| `Tz` | 平均跨零周期 | 浮点(s) |
| `Tc` | 平均波峰周期 | 浮点(s) |
| `Tp` | 谱峰周期 | 浮点(s) |
| `max_value` | 该条谱 94 格里的最大值（反量化基准） | 浮点 |
| `array_pwelch[94]` | **整条逐格谱**：94 个频格的加速度功率谱密度，各自归一化到 max_value、量化成 0–65000 的整数 | 94 个 uint16 |

> **注（2026-07 变更）**：谱格数已从 55 扩到 **94**（问题8 固件实装：`welch_bin_max` 64→103，保留频段上限从 3.25s 扩到 2s），详见下文"三、逐段数学规范"§4.2 与 `2.问题与结论.md` §4.5。`Wave_Packet` 随之增大约 78 字节（约 218 字节，仍在 `iridium_tx_buffer_size=340` 内）。

**两个关键澄清**（岸上处理全靠这两点）：

1. **它是"一维"谱，不是"方向"谱。** `array_pwelch` 是**垂向加速度**一路信号的功率谱，只告诉你"每个周期的波有多少能量"，**不含方向信息**（不知道浪从哪来）。芯片第④步其实算出了北/东两路水平加速度，但第⑤步只存垂向、把水平两路丢了（=问题7）。
2. **岸上能拿到整条谱，不只是几个标量。** `array_pwelch[94]` 是完整逐格谱，加上 `max_value` 和已知频格频率，岸上可**完整重建加速度谱**（每格 = `array_pwelch[i] × max_value / 65000`）→ 除 ω⁴ 还原位移谱 → 重算任意参数。这是"问题2 可放到岸上后处理"策略成立的前提——岸上工具 `analysis/wave_spectrum_validation/code/wave_analyzer_enhance.py` 已实现该策略，见 `2.问题与结论.md` §7。

## 三、逐段数学规范

以下给出每一步的精确公式与代码对照，供查证细节。

### 0. 总体流程（快速版）

```
833 Hz 加速度计/陀螺仪原始采样
   └─> 分块均值滤波 (n-sigma 剔除) ──> 100 Hz
        └─> AHRS / Kalman 姿态融合 (roll, pitch, yaw, 四元数)
             └─> 四元数旋转: 机体系加速度 -> NED 地理系加速度
                  └─> 分块均值滤波/降采样 ──> 10 Hz 垂向加速度 a_D[n]
                       └─> 去除重力分量 (减 9.81)
                            └─> Welch 法谱估计 (分段 + 加窗 + FFT + 平均)
                                 └─> 加速度谱 -> 海面升高(elevation)谱 (除以 ω⁴)
                                      └─> 谱矩 m0, m2, m4 -> Hs, Tz, Tc, Tp
                                           └─> 量化打包为 Wave_Packet (uint16)
                                                └─> 经 SD/串口 输出
```

下文逐段给出数学描述。

## 1. 传感器采集与坐标系旋转

代码位置：`imu_manager.cpp`，常数定义于 `imu_manager.h`。

### 1.1 原始采样与分块均值滤波

加速度计与陀螺仪以 833 Hz 采样（`nbr_micros_between_accel_gyro_readings = 1200 μs`）。每隔 `nbr_micros_between_Kalman_update = 10000 μs`（即 100 Hz 周期）对累积的一批原始样本 $\{x_i\}_{i=1}^{n}$（$n \le$ `size_dof_accumulators = 20`）做一次均值滤波（`float_mean_filter`，内部采用 n-sigma 剔除异常值后取均值），近似为：

$$
\bar{x} = \frac{1}{n'} \sum_{i \in \mathcal{S}} x_i, \qquad \mathcal{S} = \{ i : |x_i - \mu| < k\sigma \}
$$

即一种带异常值剔除的滑动平均（boxcar 低通），将 833 Hz 的高频采样在每个 100 Hz 周期内压缩为一个样本，这对应本文档附录"上游原始说明"中 "low pass filter or 9-dof to 100 Hz" 一项。

### 1.2 AHRS / Kalman 姿态融合（100 Hz）

均值滤波后的加速度 $(\bar{a}_x,\bar{a}_y,\bar{a}_z)$ 与角速度 $(\bar{\omega}_x,\bar{\omega}_y,\bar{\omega}_z)$ 输入 `Adafruit_NXPSensorFusion`（`Kalman_filter.update(...)`），磁力计输入固定为 0（代码中 `imu_use_magnetometer` 分支未启用磁力计校准，对应头文件中被注释掉的 LIS3MDL 模块）。融合输出 roll、pitch、yaw 以及姿态四元数 $q = (q_r, q_i, q_j, q_k)$。

### 1.3 机体系 → NED 地理系的四元数旋转

机体系加速度矢量 $\mathbf{a}_{\text{body}} = (a_x, a_y, a_z)$ 通过四元数旋转变换到北-东-地（NED）坐标系：

$$
\mathbf{a}_{\text{NED}} = q \otimes \mathbf{a}_{\text{body}} \otimes q^{-1}
$$

对应代码中的 `rotate_by_quat_R(&accel_raw, &quat_rotation, &accel_NED)`。输出的 D（down，垂向）分量记为 $a_D$。

### 1.4 10 Hz 降采样

每隔 `nbr_micros_between_IMU_update = 100000 μs`（即 10 Hz），对 100 Hz 的 $a_D$ 流再次做分块均值滤波，得到最终用于波浪分析的垂向加速度序列：

$$
a_D[n], \quad n = 0, 1, \dots, \qquad f_s = 10\ \text{Hz}
$$

对应本文档附录"上游原始说明"中 "vertical acceleration at 10Hz"。注意：这一级在代码中实现为均值滤波（boxcar），而非严格意义上的低通滤波器设计（如 FIR/IIR），文档措辞中的 "low pass filter" 在实现上等价于分块平均的抗混叠效果。

## 2. 谱分析前的预处理

代码位置：`wave_analyzer.cpp::gather_imu_data` / `perform_welch_analysis_imu_data`，常数定义于 `params.h`。

### 2.1 去除重力直流分量

$$
x[n] = a_D[n] - g, \qquad g = 9.81\ \text{m/s}^2
$$

对应代码：`fft_input[i] = board_data_manager.get_entry(...).accel_down - 9.81f;`

### 2.1.1 逐段去尖峰（问题3，2026-07 固件实装）

去重力后、加窗前，对每一段 $x_k[m]$ 做一次轻量去尖峰：算出该段自己的均值 $\mu_k$、标准差 $\sigma_k$，把超出 $\mu_k \pm k_\sigma \sigma_k$（$k_\sigma=$ `despike_k_sigma`，默认 10）的样本钳到边界值：

$$
x_k[m] \leftarrow \mathrm{clip}\big(x_k[m],\ \mu_k - k_\sigma \sigma_k,\ \mu_k + k_\sigma \sigma_k\big)
$$

由 `params.h::use_despike` 开关控制（默认开启）。对应代码 `wave_analyzer.cpp::perform_welch_analysis_imu_data`，位于段填充循环之后、加窗之前。详见 `2.问题与结论.md` §4.2。

### 2.2 数据量与采集时长

单次波浪测量需要采集的总样本数为：

$$
N_{\text{total}} = \texttt{total\_number\_of\_samples} = 2048 \times 6 = 12288
$$

在 $f_s = 10\,\text{Hz}$ 下对应约 $12288 / 10 = 1228.8\,\text{s} \approx 20.48$ 分钟，与本文档附录"上游原始说明"中 "for a bit over 20 minutes" 一致（实际多采集 99 个样本作为分段起止的边界余量）。

### 2.3 Welch 法分段（segmentation）

设 FFT 段长 $N = \texttt{fft\_length} = 2048$（对应 $204.8\,\text{s}$ / 段），步进 $\Delta s = \texttt{fft\_overlap} = 512$ 个样本（注：代码注释指出该常数命名易引起混淆——它表示**段间步进**而非重叠量；真实重叠样本数为 $N - \Delta s = 2048 - 512 = 1536$，即 $1536/2048 = 75\%$ 重叠，与文档描述一致）。

共使用 $K = \texttt{number\_welch\_segments} = 21$ 段，第 $k$ 段（$k = 0, \dots, K-1$）的起始样本索引为：

$$
s_k = s_0 + k \cdot \Delta s, \qquad s_0 = 50
$$

第 $k$ 段信号为 $x_k[m] = x[s_k + m],\ m = 0, \dots, N-1$。起始偏移 $s_0 = 50$ 是为了在采集的 12288+99 个样本两端留出余量（代码注释：约 100 个多余点，从其一半处开始）。

### 2.4 加窗（windowing）

每段信号在 FFT 前需加窗，代码强制要求必须启用窗函数（`static_assert`，理由是不加窗会导致谱泄漏，使 $H_s$ 偏差最高约 20%）。默认使用 Hann 窗（`use_hanning_window = true`）：

$$
w_{\text{Hann}}[m] = c_{\text{H}} \cdot \sin^2\!\left(\frac{\pi m}{N}\right), \qquad m = 0, \dots, N-1, \quad c_{\text{H}} = 1.63
$$

（注：$\sin^2(\pi m / N) = \frac{1}{2}\left(1-\cos(2\pi m/N)\right)$，与标准 Hann 窗定义等价，$c_{\text{H}}$ 为补偿加窗后信号能量损失的经验修正系数。）

可选 Hamming 窗（`use_hamming_window`，与 Hann 窗互斥）：

$$
w_{\text{Hamming}}[m] = c_{\text{M}} \cdot \left(0.54 + 0.46\cos\!\left(\frac{2\pi m}{N}\right)\right), \qquad c_{\text{M}} = 1.59
$$

加窗后的段信号为：

$$
\tilde{x}_k[m] = x_k[m] \cdot w[m]
$$

## 3. FFT 与单段周期图

代码位置：`WaveAnalyzer::perform_fft`，使用 CMSIS `arm_rfft_fast_f32`（实数 FFT，长度 2048）。

### 3.1 CMSIS 实数 FFT 输出打包格式

由于输入信号为实数，其 FFT 结果共轭对称（Hermitian），CMSIS 实现仅输出 $0 \le i \le N/2$ 的系数，并将 $X[0]$（直流）与 $X[N/2]$（奈奎斯特）的实数值打包在一起：

$$
\texttt{fft\_output} = \big[\,\mathrm{Re}(X[0]),\ \mathrm{Re}(X[N/2]),\ \mathrm{Re}(X[1]),\ \mathrm{Im}(X[1]),\ \mathrm{Re}(X[2]),\ \mathrm{Im}(X[2]),\ \dots \,\big]
$$

代码中通过索引 `2*i` 和 `2*i+1` 取出第 $i$ 个频点的实部与虚部：

```cpp
crrt_energy = fft_output[2*i]^2 + fft_output[2*i+1]^2
```

### 3.2 单段周期图（periodogram）

第 $k$ 段、第 $i$ 个频点的瞬时能量：

$$
E_k(f_i) = \mathrm{Re}\big(X_k[i]\big)^2 + \mathrm{Im}\big(X_k[i]\big)^2, \qquad f_i = i \cdot \Delta f
$$

## 4. Welch 平均与功率谱密度（PSD）归一化

代码位置：`wave_analyzer.cpp` 第 186–199 行。

### 4.1 频率分辨率

$$
\Delta f = \texttt{welch\_frequency\_resolution} = \frac{f_s}{N} = \frac{10}{2048} \approx 0.0048828\ \text{Hz}
$$

### 4.2 跨段平均与单边 PSD 缩放

对 $K = 21$ 段的周期图取平均，并应用单边 PSD 标准归一化：

$$
S_{\text{acc}}(f_i) = \frac{2}{N^2 \cdot \Delta f} \cdot \frac{1}{K}\sum_{k=0}^{K-1} E_k(f_i)
$$

代码实现为累加式：

```cpp
crrt_energy = (Re^2 + Im^2) / number_welch_segments;
working_welch_spectrum[i] += 2.0f * crrt_energy / fft_length / fft_length / welch_frequency_resolution;
```

由于 $N^2 \cdot \Delta f = N^2 \cdot (f_s/N) = N \cdot f_s$，该缩放等价于经典 Welch 谱密度公式 $S(f) = \dfrac{2}{N f_s}\langle |X(f)|^2 \rangle$，系数 2 来自将双边谱折叠为单边谱（频率范围 $[0, f_s/2]$ 内能量加倍，以保证 $\int_0^{f_s/2} S(f)\,df \approx \mathrm{Var}(x[n])$，即满足 Parseval 定理意义下的能量守恒）。

只保留频段 `welch_bin_min = 9` 至 `welch_bin_max = 103`（共 `nbr_wave_packet_freqs = 94` 个频点）：

$$
f \in [9\Delta f,\ 103\Delta f) \approx [0.0439,\ 0.4980)\ \text{Hz}, \qquad T \approx [2.0,\ 22.8]\ \text{s}
$$

该频段覆盖典型海洋重力波周期范围。

> **注（2026-07 变更）**：`welch_bin_max` 原为 64（上限 3.25s），问题8 仿真（`2.问题与结论.md` §4.5）发现短周期风浪天气下会漏看多达 27% 的能量、Hs 被材料性低估，已改为 103（上限 2.0s）。只此一处常数改动，`nbr_wave_packet_freqs`、`array_pwelch[]` 及所有循环边界均自动派生，Docker 编译验证通过（RAM +10040 字节，与预期一致）。

## 5. 由加速度谱到海面升高（elevation）谱

代码位置：`wave_analyzer.cpp` 第 217–225 行。

垂向位移 $\eta(t)$（海面升高）与垂向加速度 $a_D(t) = \ddot{\eta}(t)$ 在频域满足：

$$
\mathcal{F}\{\ddot{\eta}\}(f) = (i\omega)^2 \,\mathcal{F}\{\eta\}(f), \qquad \omega = 2\pi f
$$

故功率谱密度关系为：

$$
S_{\text{acc}}(f) = \omega^4 \cdot S_{\eta}(f) \quad\Longrightarrow\quad S_{\eta}(f) = \frac{S_{\text{acc}}(f)}{\omega^4}
$$

对应代码中的 `omega_4 = pow(2*pi*f, 4)` 及 `working_welch_spectrum[i] / omega_4`。这一步实现了从加速度谱到位移（海面升高）谱的双重积分（频域中除以 $\omega^2$ 两次）。

## 6. 谱矩与海浪统计量

代码位置：`wave_analyzer.cpp` 第 217–258 行。

### 6.1 谱矩定义

对保留频段内的离散谱 $S_\eta(f_i)$，第 $n$ 阶谱矩定义为：

$$
m_n = \sum_{i} f_i^{\,n} \cdot S_\eta(f_i) \cdot \Delta f
$$

代码中分别累加 $m_0$、$m_2$、$m_4$（变量命名为 `sqrt_m0/sqrt_m2/sqrt_m4`，循环体内实际累加的是矩本身，循环结束后才取平方根，命名上有一定误导性，但数值计算是正确的）：

```cpp
sqrt_m0 += S_eta[i] * df;                 // -> m0
sqrt_m2 += f_i^2 * S_eta[i] * df;         // -> m2
sqrt_m4 += f_i^4 * S_eta[i] * df;         // -> m4
// 循环结束后：
sqrt_m0 = sqrt(m0);  sqrt_m2 = sqrt(m2);  sqrt_m4 = sqrt(m4);
```

### 6.2 有效波高 $H_s$

$$
H_s = 4\sqrt{m_0}
$$

这是标准的（基于谱矩的）有效波高定义，$\sqrt{m_0}$ 即海面升高的标准差。代码：`Hs = 4 * sqrt_m0;`，与文献一致。

### 6.3 平均跨零周期 $T_z$ 与平均波峰周期 $T_c$

$$
T_z = \sqrt{\frac{m_0}{m_2}} \quad (T_{m02}\text{，平均跨零周期}), \qquad
T_c = \sqrt{\frac{m_2}{m_4}} \quad (T_{m24}\text{，平均波峰周期})
$$

代码：`tz = sqrt_m0 / sqrt_m2; tc = sqrt_m2 / sqrt_m4;`，与 Tucker & Pitt / IAHR 的标准定义一致。

> **✅ 已修复说明：** 此前版本的代码字面计算的是 $\sqrt{m_2/m_0}$、$\sqrt{m_4/m_2}$，即上述标准公式的倒数——用量纲分析可验证该写法算出的量纲是频率（Hz）而非周期（秒），已确认为分子分母颠倒的笔误并修正。详见 `2.问题与结论.md` 问题1。

### 6.4 谱峰周期 $T_p$

$$
T_p = \frac{1}{f_{\text{peak}}}, \qquad f_{\text{peak}} = \operatorname*{arg\,max}_{f_i} S_{\text{acc}}(f_i)
$$

代码复用了归一化打包所需的 `welch_spectrum_max_entry`（见 §7.1）对应的 bin 索引 `welch_spectrum_max_ind`，换算为 `tp = 1 / ((welch_spectrum_max_ind + welch_bin_min) * welch_frequency_resolution)`。

> **注意：** 这里的最大值是在**加速度谱** $S_{\text{acc}}(f)$（除以 $\omega^4$ 之前）上找的，而非位移/海面升高谱 $S_\eta(f)$ 上的峰值；两者峰值位置理论上可能不同（$\omega^{-4}$ 加权会把能量谱的相对形状向低频偏移）。SWIFT/NIWA 等参照浮标是在能量谱上取峰值（见 `2.问题与结论.md` 问题6），这是当前实现与参照做法的已知细微差异，为复用已有的最大值查找逻辑（同一个值也用于 §7.1 的量化基准）而采用，如需更严格对齐可在后续版本中改为在 $S_\eta(f)$ 上单独查找峰值。

## 7. 量化打包与传输

代码位置：`wave_analyzer.cpp` 第 260–283 行，结构体定义见 `wave_analyzer.h::Wave_Packet`。

### 7.1 归一化与 16 位量化

先求保留频段内谱的最大值：

$$
S_{\eta,\max} = \max_i S_\eta(f_i)
$$

每个频点量化为 16 位无符号整数：

$$
\texttt{array\_pwelch}[i] = \left\lfloor \frac{S_\eta(f_i)}{S_{\eta,\max}} \times 65000 \right\rfloor
$$

（采用 65000 而非 65535 留出余量以避免四舍五入溢出。）$S_{\eta,\max}$ 本身以浮点数形式存入 `Wave_Packet.max_value`，接收端可据此反量化还原：

$$
\hat{S}_\eta(f_i) = \frac{\texttt{array\_pwelch}[i]}{65000} \times \texttt{max\_value}
$$

（对应 `print_wave_packet` 中的还原公式 `array_pwelch[i] * max_value / 65000.0f`。）

### 7.2 打包字段

`Wave_Packet` 结构体（`wave_analyzer.h`）包含：`posix_timestamp`、`spectrum_number`、`Hs`、`Tz`、`Tc`、`Tp`、`max_value`、`array_pwelch[94]`，经 `WaveAnalyzer::write_message_to_buffer` 以 `'Y' + 原始字节 + 'E'` 的形式写入待发送缓冲区，最终写入 SD 卡 WAVES.CSV / 串口输出（铱星模块本版未贴装，见本文档"二、采集与上传流程"）。

## 附录：上游原始说明（英文精简版）

以下为上游 `gauteh/omb-nano` 自带的原始处理流程说明（英文，精简），保留以便对照溯源；正文"二""三"两节是对它的详细展开与数学化。

```
- buffering: both the GNSS and wave spectra packets are buffered using a deque
  (double ended queue). The newest messages are always transmitted first.
- wake up at fixes UTC times
- GNSS: several fixes; timeout
- wave spectra:
  -- IMU
     --- 9-dof at 833kHz (accel, gyro)
     --- for now, not magnetometer
     --- low pass filter or 9-dof to 100 Hz
     --- Kalman filter at 100 Hz
     --- low pass filter of Kalman output
     --- vertical acceleration at 10Hz
  -- processing
     --- measurements for a bit over 20 minutes of wave vertical acceleration
     --- welch method by:
         ---- segments of 2048 points at 10Hz, with 75% overlap
         ---- take rfft, and compute the energy at each frequency
         ---- average the energy over the segments to compute the welch spectrum,
              which is some amplitude square of spectra
  -- packaging
     --- keep only the relevant bins
     --- package into uint16 by 1) computing max value of spectrum on the selected
         bins, 2) use it to normalize between 0 and 65000
  -> so the wave spectrum transmitted is the "Welch energy spectrum (quadratic)
     of the vertical acceleration, over relevant bins"
```
